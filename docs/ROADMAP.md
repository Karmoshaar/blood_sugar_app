# خطة إنهاء المشروع (10 مراحل)

> **طريقة العمل الموفّرة للتوكن:** مرحلة واحدة لكل جلسة. ابدأ الجلسة بجملة:
> «اقرأ `docs/ROADMAP.md` و`README.md` ونفّذ المرحلة N».
> علّم ☑ على المهام المنتهية حتى تعرف الجلسة التالية من أين تبدأ.
>
> 👤 = مهمة عليك (قرار أو تجربة على جهاز) · 🤖 = مهمة برمجية

## ✅ ما تم قبل هذه الخطة
- تحويل المشروع إلى Feature-First (core + features بطبقات domain/data/presentation).
- حفظ محلي للقراءات والملف الشخصي والإعدادات، وإصلاح التنقل وأول شاشة.
- نوع القراءة، تعديل/حذف مع تراجع، الوحدات mg/dL و mmol/L، رسوم بمحاور ونطاق مستهدف.
- إعدادات Android للإشعارات، و20 اختباراً ناجحاً.

---

## المرحلة 1: التثبيت والدمج
- [ ] 👤 تشغيل التطبيق على جهاز حقيقي (Android، ثم iOS إن وجد).
- [ ] 👤 تجربة التذكير: ضبطه بعد دقيقتين، ثم إعادة تشغيل الهاتف والتأكد أنه يبقى.
- [ ] 👤 إرسال أي خطأ يظهر **بنصه الكامل** (لقطة أو نسخ).
- [ ] 🤖 إصلاح ما يظهر في التجربة.
- [ ] 🤖 فتح Pull Request إلى `main` والتأكد أن CI أخضر، ثم 👤 الدمج.

## المرحلة 2: الهوية والاسم
- [ ] 👤 اعتماد الاسم نهائياً (مقترح: «قطرة / Qatra») وفحص المتجر والنطاق.
- [ ] 🤖 تغيير اسم التطبيق في Android وiOS والعناوين داخل الشاشات بدل «Pulsey».
- [ ] 🤖 تغيير `applicationId` / Bundle ID من `com.example...` (قبل أي نشر، لا يتغير بعده).
- [ ] 🤖 تعديل نصوص صفحات التعريف لتتكلم عن السكر بدل نبض القلب والطبيب الذكي.
- [ ] 👤 تجهيز أيقونة وشعار. 🤖 توليد الأيقونات بـ `flutter_launcher_icons`.

## المرحلة 3: اللغة العربية والاتجاه RTL
- [ ] 🤖 إضافة `flutter_localizations` وملفات `arb` (عربي + إنجليزي).
- [ ] 🤖 نقل كل النصوص من الشاشات إلى ملفات الترجمة.
- [ ] 🤖 إضافة خط عربي (مثل Tajawal أو Cairo) والتأكد من الاتجاه RTL في كل الشاشات.
- [ ] 🤖 خيار تغيير اللغة من الإعدادات.
- [ ] 👤 مراجعة الترجمة العربية.

## المرحلة 4: التحليل الصحي
- [ ] 🤖 السكر التراكمي التقديري (eA1c) مع تنبيه أنه تقدير وليس تحليلاً.
- [ ] 🤖 نسبة الوقت داخل النطاق (Time in Range) في بطاقة الملخص.
- [ ] 🤖 حدود مختلفة حسب نوع القراءة (صائم / بعد الأكل).
- [ ] 🤖 تنبيه فوري عند الهبوط (< 70) مع «قاعدة الـ15»، وعند الارتفاع الشديد.
- [ ] 👤 مراجعة النصوص الطبية (يُفضّل مع طبيب أو صيدلي).

## المرحلة 5: تحسين تسجيل القراءات
- [ ] 🤖 اختيار تاريخ ووقت القراءة (لتسجيل قراءة سابقة).
- [ ] 🤖 ملاحظة اختيارية مع كل قراءة (أكل، رياضة، دواء).
- [ ] 🤖 فلترة السجل حسب الفترة: 7 / 30 / 90 يوماً، والإحصائيات حسب الفترة.
- [ ] 🤖 اختبارات للميزات الجديدة.

## المرحلة 6: الرسوم والتقارير
- [ ] 🤖 اختيار فترة الرسم (أسبوع / شهر) وتلوين النقاط حسب الحالة.
- [ ] 🤖 تقرير PDF (ملخص + رسم + جدول) بحزمة `pdf`.
- [ ] 🤖 زر مشاركة التقرير (`share_plus`) لإرساله للطبيب.
- [ ] 👤 مراجعة شكل التقرير.

## المرحلة 7: التذكيرات الذكية
- [ ] 🤖 أكثر من تذكير في اليوم، وتفعيل/إيقاف كل واحد.
- [ ] 🤖 تذكير تلقائي بعد ساعتين من قراءة «قبل الأكل».
- [ ] 🤖 الضغط على الإشعار يفتح نافذة إضافة قراءة مباشرة.
- [ ] 👤 تجربة الإشعارات على Android وiOS.

## المرحلة 8: البيانات والحساب
- [ ] 👤 **قرار:** Firebase أو حذف شاشة التسجيل والبقاء محلياً.
- [ ] 🤖 تصدير واستيراد القراءات كملف CSV (نسخة احتياطية يدوية).
- [ ] 🤖 إذا اخترت Firebase: تسجيل دخول (Google/Apple/بريد) + `RemoteReadingsRepository` ومزامنة.
- [ ] 🤖 إذا لا: حذف شاشة التسجيل وأزرار الدخول الشكلية.
- [ ] 🤖 خيار «حذف كل بياناتي» في الإعدادات.

## المرحلة 9: الجودة والمظهر
- [ ] 🤖 الوضع الليلي (Dark Mode) عبر ألوان الثيم بدل الألوان الثابتة.
- [ ] 🤖 دعم تكبير الخط وتباين الألوان (Accessibility).
- [ ] 🤖 اختبارات لشاشة الإعدادات والتقارير، وبناء APK في CI.
- [ ] 🤖 إزالة أي كود أو ملفات أو حزم غير مستخدمة.

## المرحلة 10: النشر
- [ ] 👤 إنشاء حساب Google Play Console (و Apple Developer إن أردت iOS).
- [ ] 🤖 مفتاح توقيع release وإعداد `build.gradle.kts` (المفتاح نفسه يبقى عندك فقط).
- [ ] 🤖 صفحة سياسة خصوصية (إلزامية لتطبيقات البيانات الصحية) وتنبيه طبي داخل التطبيق.
- [ ] 🤖 نصوص صفحة المتجر بالعربي والإنجليزي. 👤 لقطات الشاشة.
- [ ] 👤 نشر نسخة اختبار داخلي (Internal testing / TestFlight)، ثم النشر العام.

## نصائح لتوفير التوكن
1. **جلسة واحدة = مرحلة واحدة.** الجلسات الطويلة تكلّف أكثر لأن كل رسالة تحمل كل ما قبلها.
2. **أعطِ القرارات مسبقاً** في أول رسالة (الاسم، Firebase أم لا، الألوان) بدل أسئلة وأجوبة.
3. **عند الخطأ أرسل نصه كاملاً** مع خطوات حدوثه، بدل «ما اشتغل».
4. **المهام 👤 اعملها بنفسك قبل الجلسة**، فهي لا تحتاج توكن.
5. **لا تطلب مراجعة كاملة للمشروع** مرة أخرى؛ `README.md` وهذا الملف يكفيان لأي جلسة جديدة.
